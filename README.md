# 跨 Agent 工作协调机制 / Cross-Agent Work Coordination

> 一套用于**多个 AI Agent 在同一文件系统上协作**的协调机制：文档、模板与工具。
> **它不是"最佳实践清单"——每条规则都对应一次真实故障。**

A coordination mechanism for **multiple AI agents collaborating on the same filesystem**:
rules, templates, and tooling. Every rule traces back to a real incident.

---

## 一、解决什么问题

| # | 故障模式 | 后果 |
|---|---|---|
| **F1** | **确认没有绑定版本** | A 确认了某文件，B 随后改了它 → 「已确认」其实已失效，**双方都不知道** |
| **F2** | **交接没有公共载体** | 双方各自产出「回复.md」来回传 → 版本分叉、无法追溯 |
| **F3** | **监视基线会自动重置** | 监视器重启以「此刻」为基线 → **重启前刚发生的对方写入被静默吃掉** |
| **F4** | **没人知道对方还在不在** | 「沉默」既可能是「没新消息」，也可能是「对方已经停了」——**无法区分** |

对应四条核心机制：**指纹绑定 / 单一载体 / 持久基线 / 心跳**。

## 三、核心规则一览

| 规则 | 内容 | 由哪次故障催生 |
|---|---|---|
| **R1** | **确认只对「指纹」有效**（字节数 + sha256 前 12 位）；指纹一变，先前结论自动降级为「需重核」 | 确认未绑定版本 → 确认静默失效 |
| **R2** | **单一交接载体**：按作者分段，只追加自己条目；一律写绝对时间 | 双方各自产出回复文件 → 版本分叉 |
| **R3** | **持久基线，永不自动重置**：基线只在「处理完毕」后推进 | 监视器重启吃掉对方的写入 |
| **R4** | **心跳独立于监视器**：监视器「命中即退出」，心跳必须单独成任务 | 共用任务 → 一报警手表自己先失联 |
| **R5** | **轻量重核**：点状修改只需确认该点，避免「改一行、全文重核」死循环 | 指纹制副作用 |
| **R6** | **派生物责任**：谁渲染谁重导；另一方只需指出「源已改、产物过期」 | 导出物过期无人认领 |
| **R7** | **时间必须机器生成**：条目时间一律由 `date` 产生，禁止手写 | 手写标题时间提前 7 分钟，由对方发现 |
| **R8** | **事故即规则**：每次故障都记档并追加/修正一条规则 | 元规则 |

## 四、快速开始

```bash
# 1) 复制模板
cp 工作协调.模板.md <工作目录>/工作协调.md
cp 心跳检查.模板.sh <工作目录>/心跳检查.sh
cp 冲突检测.模板.sh <工作目录>/冲突检测.sh
cp 人类待办横幅.模板.sh <工作目录>/人类待办横幅.sh
cp 人类待办.模板.tsv <工作目录>/人类待办.tsv

# 2) 替换 工作协调.模板.md 中的全部 <...> 占位符（填项目名、双方代号、文件清单）

# 3) 建立监视基线（只在首次；此后永不重建）
touch <工作目录>/.watch_marker

# 4) 登记交付物指纹
for f in <交付物通配>; do printf "%-40s %s\n" "$f" "$(shasum -a 256 "$f" | cut -c1-12)"; done

# 5) 起监视器与心跳（脚本见指导书 §五；两者必须是独立任务）
```

**第一条 DONE 应包含**：谁、何时、登记了哪些文件及其指纹、监视/心跳参数、以及**给对方的第一件待办**。

## 五、设计原则（比规则更重要）

1. **没有故障支撑的规则不要加。** 规则越多，越没人遵守。
2. **宁可重复报警，绝不漏报。** 持久基线的代价是可能重复提醒——这是刻意选择。
3. **指纹只证明「是同一份文件」，不证明「内容对不对」。** 前者可自动验证，后者仍需人的判断。
4. **人类通道必须显式设计。** 文件提醒只在人读文件时有效；真正能主动触达人的是**对话**。否则「机制很完善」的错觉会掩盖它。
5. **自查有结构性盲区。** 在本项目的 4 次事故中，**3 次的发现者是对方或用户**，只有 1 次是自查。所以他查不可替代。

## 六、实测数据（来自一次 27 条目的真实日志）

| 观测 | 结果 |
|---|---|
| 跨作者「同一分钟」相邻写入 | 1 处 ← 分钟精度下的并发窗口 |
| 时间倒挂（物理顺序 ≠ 时间顺序） | 1 处 → **不能假设「文件末尾 = 最新」** |
| 带秒级时间戳的条目 | 0/27 → 无法检测真并发（→ 催生 R7） |
| 4 次事故的发现者 | 用户 2 ／ 对方 1 ／ 自查 1 |

---

## 七、局限

- **心跳只有双方都写才有意义**；缺一方 → 「对方在不在」仍不可判
- **并发保护依赖双方遵守**；没人用的锁比没有锁更糟（虚假安全感）
- **管不住不在文件里的人**——必须由人完成的动作，机制只能做到「把后果说清楚、把倒计时摆到眼前」
- **机制会自我膨胀**：协调本身消耗注意力，需定期自问「这些规则还在解决真实问题吗」
